# Synthetic End-to-End Conversion Contract

The synthetic T22 suite proves the deterministic artifact pipeline using only self-authored USDA text and generated bytes. It does not use an Unreal, Unity, or Godot Editor installation, third-party project, proprietary package payload, or graphical screenshot comparison.

## Verified Flow

The `end_to_end_conversion` integration suite executes the following owned path twice where determinism matters.

| Stage | Verified behavior |
|---|---|
| Source selection | A root-confined USDA fixture is resolved through `UsdStageInspector` with an explicit render purpose, forbidden payloads, and universal context. Repeated resolution produces equal selected facts and prim hierarchy. |
| Canonical scene | The fixture’s typed USD source identity is retained in `SourceLink`; a self-authored canonical triangle, camera, and point light are graph-validated. The bounded USDA adapter remains `requires_adapter` for full semantic composition, so the suite does not claim generic USD conversion. |
| Package | `GlbWriter` packages the validated canonical scene twice. The resulting GLB bytes and SHA-256 hash are equal, and the output includes mesh, camera, and punctual-light structures. |
| Publication | `AtomicArtifactStore` publishes the manifest and GLB once, reuses the verified directory on the second identical request, and verifies the declared artifact hash before runtime use. |
| Bevy load | The Bevy 0.19 app uses the root-confined published conversion path. Dynamic GLTF world spawning retains `WorldAssetRoot` and Vortex provenance after the asset resolves headlessly. |
| Failure behavior | Malformed USDA, attempted output-root escape, and post-publication GLB corruption are rejected. Corruption creates `VortexRuntimeDiagnostic` rather than a Vortex scene root. |

The app explicitly registers the reflected Bevy 0.19 components emitted by the GLTF world spawner for dynamic mesh, material, GLTF labels, camera, light, visibility, AABB, and frustum entities. This makes current headless GLTF scene spawning exercise the same runtime mechanism used by the desktop viewer.

## Compatibility Matrix

[`compatibility_matrix.json`](compatibility_matrix.json) is generated with:

```bash
cargo run -q -p vortex-bevy -- support-matrix --format json \
  > docs/compatibility_matrix.json
```

It is the serialized output of the same typed core support-matrix query that the CLI uses. The file labels bounded source adapters and human-gated Editor work as `requires_adapter`, protected Unreal content as `rejected`, and the tested deterministic package/publication/runtime/synthetic-fixture boundaries as `converted`.

## Real-Editor Gate

T22 remains **in progress**, not complete. Its real-project acceptance path requires an authorized, redistributable Unreal sample project and a matching Editor version supplied or explicitly approved by the project owner. When available, the opt-in smoke test must use the checked-in bridge, must not place assets or credentials in CI, and must keep the synthetic suite mandatory.

> The synthetic suite proves reproducible owned-fixture boundaries. It is not evidence that arbitrary Unreal, Unity, USD composition, shaders, scripts, or proprietary project behavior has been converted faithfully.
